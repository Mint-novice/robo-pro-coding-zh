# 3 · 校验与验收

## 3.0 为什么需要三层

汉化的失败模式有三种，每一种都能单独骗过眼睛：

| 失败模式 | 表现 | 只有哪层能抓到 |
|---|---|---|
| 译文错位 | 条目数量对、界面也"是中文"，但 `%1/%2` 换了位、按钮文案串行 | 第 1 层：占位符/键集校验 |
| 打包错 | 文件都在，`app.asar` 起不来或白屏 | 第 2 层：逐文件回读比对 |
| 跑错 | 都正常，但语言下拉里没有"中文"或选了不生效 | 第 3 层：CDP 读真实 DOM |

所以验收必须三层都过，缺一层就等于没验。

---

## 3.1 第 1 层：条目层

```bash
node tools/validate-i18n.js i18n
```

逐对比对 `i18n/en/*.json`（官方英文原文）与 `i18n/zh/*.zh.json`：

| 检查 | 判据 | 本次结果 |
|---|---|---|
| 键集相等 | 缺键 = 0、多键 = 0 | 0 / 0 |
| 非空 | 空串/纯空白 = 0 | 0 |
| 占位符 | `%n` 的多重集完全相等（编号与数量） | 0 处不匹配 |
| 富文本 | `<x id="…" equiv-text="…"/>` 数量与逐个字符串相等 | 0 处不匹配 |
| 条目总数 | 与 `grep -c '<trans-unit'` 一致 | 861+128+28 = 1017 |

期望输出：

```
{"name":"cm-01","src":28,"out":28,"bad":0,...}
{"name":"ctrl-01","src":128,"out":128,"bad":0,...}
{"name":"rpc-01","src":108,"out":108,"bad":0,...}
…
TOTAL_ENTRIES 1017 PROBLEMS 0
```

`PROBLEMS` 不是 0 就不要往下走。

---

## 3.2 第 2 层：打包层

```bash
node tools/pack-asar.js build out/app.asar
node tools/verify.js out/app.asar build
```

`verify.js` 用 asar header 里的 `offset/size` 把每个文件从新包里读出来，与源目录逐字节 `Buffer.equals`：

```
entries=1953 checked=1953 mismatched=0 missingSrc=0
zh files: client/www/assets/npx-robo-pro-coding/i18n/messages.zh.xlf (…),
          client/www/assets/npx-controller/i18n/messages.zh.xlf (…),
          client/www/assets/ngx-codemirror/i18n/messages.zh.xlf (…)
```

三个数必须满足 `mismatched=0`、`missingSrc=0`，且 `zh files` 恰好 3 个。少一个 `messages.zh.xlf` 就有一块界面还是英文。

> 顺手提醒：`pack-asar.js` 会跳过 `*.orig`。改 `main.*.js` 前先 `cp main.js main.js.orig`，一方面留回滚，一方面避免把备份打进包里。

## 3.3 第 3 层：运行时层

启动汉化副本并开调试端口：

```powershell
$env:ELECTRON_RUN_AS_NODE=""    # 必须清，否则 Electron 退化成 node，一闪即退
& "$env:LOCALAPPDATA\Programs\ROBOProCoding-zh\app\ROBO Pro Coding.exe" `
  --user-data-dir="$env:LOCALAPPDATA\ROBOProCoding-zh-data" --remote-debugging-port=9222
```

用 CDP 读真实 DOM（`http://127.0.0.1:9222/json` → `Runtime.evaluate` → `document.body.innerText`），逐界面抽查：

| 界面 | 断言文本 |
|---|---|
| 首页 | `新建项目…`、`创建一个新的空项目，或使用示例项目。`、`加载项目…` |
| 主菜单 | `首选项`、`设置`、`项目`、`最近使用的项目`、`帮助`、`发行说明`、`隐私政策` |
| 新建项目向导 | `为新项目选择选项`、`图形化编程`、`控制器`、`TXT 4.0 Controller`、`取消`、`下一步`、`创建` |
| 设置 → 语言 | `语言`、`中文`、`控制开发环境的语言。`，下拉共 9 项，第 9 项为 `中文` |

判据：以上文本全部命中；语言下拉项数 `= 9`。截图存档（`docs/screenshot-home.png`）。

**别用"我看着是中文"当验收**：AOT 插入出错时的典型表现是设置页能开、但下拉少一项或选完不生效——只有读 DOM 才能发现。

## 3.4 已知坑（按踩到的顺序）

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | 双击启动一闪即退，退出码 9，`bad option:--no-sandbox` | 环境里有 `ELECTRON_RUN_AS_NODE=1`，Electron 退化当 Node 跑 | 启动器里 `set "ELECTRON_RUN_AS_NODE="` |
| 2 | 直接读写 `C:\Program Files\WindowsApps\…` 报拒绝访问 / EFS 加密错 | Store 包目录受 ACL + EFS 保护 | 先 `copy-app.js` 整份复制到 `%LOCALAPPDATA%\Programs\`，只动副本 |
| 3 | 改了 asar 后启动白屏且 DevTools 无 JS 报错 | 打包 header 不对（未按名排序 / offset 未顺序分配 / padding 错） | 用 `pack-asar.js`，再用 `verify.js` 回读；不要手搓 header |
| 4 | 设置页出现两个"中文"或下拉项错位 | AOT 重排时把 `<33` 的索引也一起加了 | 重排阈值写死 `>=33`，并断言命中数（>20 / =4 / =7）。数量变了就是新版本模板变了，停下来重定位 |
| 5 | 语言切中文后个别积木块仍英文 | 该串来自控制器/编译器运行时，不在 XLF 内 | 属已知边界，不追 |
| 6 | 升级后改动"默默失效"（还是英文但不报错） | 新版 `messages.zh.xlf` 被覆盖 | 每次升级重跑流水线；`build-xlf.js` 的 `missing` 计数就是进度条 |
| 7 | 译文里 `{{ 0 }}` 被美化掉，界面显示空 | 把 `<x …/>` 当普通文本处理了 | 第 1 层 `tagBad` 会抓到；翻译时严禁改动标签内属性 |

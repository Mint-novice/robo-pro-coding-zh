# 1 · 方法论：把 Electron + Angular 桌面应用汉化，跑成一条可复现的流水线

本文是**通用方法**，以 ROBO Pro Coding 6.5.4 为实例。照着做，任何「Electron 壳 + Angular 前端 + ngx-translate/XLF」的桌面应用都能复用；换成别的 i18n 机制（i18next / vue-i18n / Qt .ts）时，只需替换第 3、5 步的解析器，骨架不变。

---

## 0. 总览：六步，每步都有"过/不过"的判据

| 步 | 动作 | 产出 | 判据（不过就停） |
|---|---|---|---|
| 1 | 侦察技术栈 | 结论：i18n 机制、语言枚举位置、有无完整性校验 | 能定位到 `messages.<lang>.xlf` 与语言枚举 |
| 2 | 解包 asar | `extracted/` 只读副本 | 文件数、总大小自洽；`package.json` 版本可读 |
| 3 | 抽取条目 | `i18n/en/*.json` + 切片 | 条目数与 `grep -c '<trans-unit'` 一致 |
| 4 | 批量翻译 | `i18n/zh/*.zh.json` | 键集相等、`%n` 相等、`<x/>` 相等、无空值 |
| 5 | 回填 | `messages.zh.xlf` + 已做语言改动的 `main.*.js` | 生产 xlf 无 missing；patch 断言全 OK |
| 6 | 重打包 + 验收 | 新 `app.asar` | 逐文件回读一致 + 真实 DOM 抽查 |

---

## 1. 侦察：先确认"能不能翻译"，再谈怎么翻译

只查四件事，别写代码：

```bash
# 1) 是不是 Electron：看 resources/ 下有没有 app.asar
dir "C:\Program Files\WindowsApps\beemo.ROBOProCoding_6.5.4.0_x64__*\resources"

# 2) 语言资源在哪：解包后全局搜 xlf / json 语言包
tools/asar.js <app.asar> . list

# 3) 语言枚举在哪：main.*.js 里搜官方语言码的连写形式
#    本例：,u.UA="ua",u}(nd||{})   ← 最后一种语言后面紧跟 IIFE 收尾，是最稳的锚点

# 4) 有没有完整性校验：搜 integrity / asarIntegrity / signature
#    若 electron-builder 配了 asarIntegrity，改 asar 会在启动时被拒——必须先处理
```

ROBO Pro Coding 的结论：

- 8 种官方语言：`de / en / es / fr / nl / pt / ru / ua`，**无 `zh`**；
- 三套独立 i18n 资源，各自一套 XLF：
  ```
  client/www/assets/npx-robo-pro-coding/i18n/messages.<lang>.xlf   主程序（861 条）
  client/www/assets/npx-controller/i18n/messages.<lang>.xlf        控制器面板（128 条）
  client/www/assets/ngx-codemirror/i18n/messages.<lang>.xlf        代码编辑器（28 条）
  ```
- 运行时由自定义 XLF loader 按 `messages.${lang}.xlf` 拉取 ⇒ **加文件 + 加枚举 + 加下拉项**即可，不必重编译，不必碰业务代码。

> 这一步决定了后面全部工作量。如果发现语言是编译期写死（或字符串直接内联在模板里），就转成"重编译前端源码"路线，成本高一个数量级——那也是本方法唯一不适用的情况。

## 2. 解包 asar（不写回系统目录）

asar 格式（自己实现 60 行就够，不必装依赖）：

```
offset 0  : uint32 = 4                 // header 前 4 字节的固定值
offset 4  : uint32 = headerSize        // 8 + payload
offset 8  : uint32 = payloadSize
offset 12 : uint32 = jsonLen
offset 16 : json (UTF-8)               // 目录树：{files:{…}}，叶子 {size, offset}
pad → dataOffset = 8 + headerSize      // 之后是顺序拼接的文件数据
```

```bash
node tools/asar.js "<…>\resources\app.asar" . list              # 只列目录
node tools/asar.js "…\app.asar" extracted extract "assets/.*xlf" # 只抽语言包（推荐）
node tools/asar.js "…\app.asar" . find "main\..*\.js"            # 找主 bundle
```

**纪律**：源文件永远只读。Windows Store 的 `WindowsApps` 目录同时受 ACL 与 EFS 保护，先把它整份复制到可写目录（`tools/copy-app.js`），所有改动只发生在副本上，原版随时可回退。

## 3. 抽取条目：把 XLF 拍平成可翻译的 JSON

`<trans-unit>` 是翻译单元，`id` 是键，`<source>` 是原文：

```bash
node tools/dump-units.js extracted/client/www/assets/npx-robo-pro-coding/i18n/messages.en.xlf i18n/en/rpc.all.json
# units: 861  with placeholder: 163  empty source: 0     ← 另有 17 条含 <x …/> 富文本占位
```

拍平后按 100~110 条切片（`tools/split.js`），一片一个批次——这是为了让翻译可以**并行**，并且每片都能单独校验：

```
rpc-01…rpc-08  = 861 条（8×108，末片 105）
ctrl-01        = 128 条
cm-01          =  28 条
合计            = 1017 条
```

---

## 4. 批量翻译：规则比模型重要

给翻译方的约束（缺一条就会出现"看着像中文、用起来报错"的版本）：

1. **键必须一一对应**：不许增、不许删、不许改键名。
2. **占位符 `%1…%6` 原样保留，编号与顺序不变**——它们由运行时按位置替换，顺序变了就串位。
3. **富文本标签原样保留**：`<x id="INTERPOLATION" equiv-text="{{ 0 }}"/>`、`<x id="INTERPOLATION_1" …/>` 连属性值里的空格都不能动；只翻译标签之间的文字。
4. **术语按表**（[2-术语表.md](2-术语表.md)）：同一英文词全篇同一译法，`Controller` 一律「控制器」、`Encoder motor` 一律「编码电机」。
5. **不翻译**：产品名 `ROBO Pro Coding`、`TXT 4.0 Controller`、`fischertechnik`、`MQTT`、`JSON`、`LED`、代码标识符。
6. **长度意识**：按钮/标签会截断，中文比英文短通常安全；但 `*_TITLE` 这类是拼进积木块的槽位文案，必须按 `%n` 顺序读得通。
7. **标点**：全角中文标点（，。：？），句末保留原文的句号/问号语义。
8. **可疑原文不要擅自"修"**：本例 `FT_DISPLAY_GET_SLIDER_STATE_TITLE` 原文 `i%1 is slider %2 enabled` 开头有孤立 `i`（源文件笔误），译文按「%1 滑块 %2 是否启用」处理并在 PR 里注明——**记下来，别默默吞掉**。

校验（`tools/validate-i18n.js`，纯 Node）：

```bash
node tools/validate-i18n.js i18n
# {"name":"rpc-01","src":108,"out":108,"bad":0,"empty":0,"phBad":0,"tagBad":0,"missing":0,"extra":0}
# …
# TOTAL_ENTRIES 1017 PROBLEMS 0
```

## 5. 回填：三处改动

### 5.1 生成 `messages.zh.xlf`

`tools/build-xlf.js` 以官方 `messages.en.xlf` 为骨架，把译文塞进 `<target>`（已有则替换、没有则插入、`<target/>` 自闭合则展开），并把 `target-language` 改成 `zh-CN`：

```bash
node tools/build-xlf.js …\messages.en.xlf …\messages.zh.xlf i18n/zh/rpc-01.zh.json … i18n/zh/rpc-08.zh.json
# replaced=0 inserted=861 missing=0
```

**缺译自动回退英文**（`missing` 计数）——这就是为什么升级后可以先跑通、再补译。

### 5.2 语言枚举

```js
// 原样：  … ,u.UA="ua",u}(nd||{})
// 改枚举：… ,u.UA="ua",u.ZH="zh",u}(nd||{})
```

用"最后一种语言的字面量 + IIFE 收尾"作锚点，比搜 `LANGUAGE` 之类语义词稳得多。

### 5.3 Angular AOT 模板插入（全工程唯一的硬骨头）

设置页的组件模板在打包后是**预编译的指令调用序列**，形如：

```js
selectors:[["app-settings"]],features:[Ln],decls:62,vars:41,consts:[…,
  v(31,"mat-option",12),Ce(32,"Українська"),L(),
  …
],vars:…, …update:function(t,s){…Xe(33,["value"],…)…},…},
dependencies:[…]
```

这里：`v(idx,"mat-option",12)` 是"创建元素"指令，**首参是节点索引**；`decls` 是元素声明总数；`vars` 是绑定槽位总数；update block 里用 `Xe(idx, […])` 反向引用同一节点。索引是**硬编码的连续整数**，中间插节点等于把后面所有引用整体错位。

正确做法（`tools/patch-main.js`，全程带断言）：

| 步骤 | 动作 | 本例数值 | 断言 |
|---|---|---|---|
| ① 定位 | 从 `selectors:[["app-settings"]],…,decls:…,vars:…,consts:[` 到 `dependencies:[…]` | — | 两个锚点都存在且顺序正确 |
| ② 抬计数 | `decls:62`→`decls:64`（+2 个元素）、`vars:41`→`vars:42`（+1 个绑定槽） | 62→64 / 41→42 | — |
| ③ 重排 create | 所有 `v|Ce|Be|Dt|We(N≥33,…)` 的 N 加 2 | 命中 >20 处 | `renumberCreate > 20` |
| ④ 重排链式 | 链式元素调用 `)(N≥33,"mat-label")` 的 N 加 2 | 命中 4 处 | `=== 4` |
| ⑤ 插入节点 | 在乌克兰语 option 之后插入 `v(33,"mat-option",12),Ce(34,"\u4e2d\u6587"),L()` | 33/34 即被抬空的两个索引 | UA option 正则必须命中 |
| ⑥ 重排 update | update block 里 `Xe(N≥33,` 的 N 加 2 | 命中 7 处 | `=== 7` |
| ⑦ 绑值 | `Wn("value",h.LANGUAGE.UA),` → 追加 `A(2),Wn("value",h.LANGUAGE.ZH),` | `A(2)`=分配第 2 号槽 | UA 绑定必须命中 |

三条经验，比代码本身值钱：

- **先抬计数、再改索引、最后插节点**。顺序反了，插入的节点会被自己的重排吃掉。
- **每个数量都写死断言**（`>20`、`=== 4`、`=== 7`）。新版本一旦重排，脚本立刻 FAIL，而不是生成一个启动就白屏的 `main.js`——这是"可复现"和"碰运气"的分界。
- **不要在 AOT 产物里做正则大范围替换**。只在该组件的 create/update block 切片内替换，切片外一个字节都不动。

## 6. 重打包 + 三层验收

```bash
node tools/pack-asar.js build out/app.asar          # packed 1953 files, data 45086253 bytes
node tools/verify.js out/app.asar build             # entries=1953 checked=1953 mismatched=0 missingSrc=0
```

`pack-asar.js` 要严格遵守格式：**目录按名称排序、offset 顺序分配、header 4 字节对齐**；`verify.js` 则按 header 里的 `offset/size` 把每个文件读回来与源目录逐字节比对。这一步能抓住 90% 的"改完打不开"。

第三层是运行时（只能真机验）：

```
Electron --remote-debugging-port=9222 → CDP → Runtime.evaluate 读 document.body.innerText
```

本例抽查四个界面：首页（`新建项目…`/`加载项目…`）、主菜单（`首选项`/`设置`/`最近使用的项目`）、新建项目向导（`图形化编程`/`TXT 4.0 Controller`）、设置页（`语言 / 中文`，下拉 9 项）。

## 7. 迁移到别的应用：改哪里

| 环节 | 换应用时怎么改 |
|---|---|
| 语言资源格式 | i18next/vue-i18n：JSON 树，写"树拍平/回填"两个函数替换 `dump-units`/`build-xlf`；Qt：`lconvert` + `.ts` |
| 语言枚举 | 搜官方语言码的连写（`"de","en",…,"ua"`），或搜 `SUPPORTED_LOCALES` / `availableLanguages` |
| 语言下拉 | 若是 JIT/运行时数据驱动（数组 push 即可）→ 无痛；若是 AOT 模板 → 按 §5.3 走 |
| 完整性校验 | 搜 `asarIntegrity`。**本项目不提供任何规避完整性校验的做法**：若该应用对 asar 做完整性校验，本项目即不适用于它，请改用不修改 asar 的路径（如只在用户目录注入语言资源），或放弃该应用 |
| 签名 | 改副本一般无需重签（Windows 不校验目录内文件签名，除非 AppLocker/WDAC 策略强制） |
| 自动更新 | 本地化副本是一次性快照，官方后续升级不会作用于它；要跟随新版本就按 `docs/4` 重建。本项目**不修改**任何更新配置或更新通道 |

## 8. 边界与自检

- 只改**副本**，系统目录零写入；回滚 = 删两个目录。
- `ELECTRON_RUN_AS_NODE=1` 会让 Electron 退化为 Node 进程，表现为"一闪即退、退出码 9、bad option:--no-sandbox"。启动器必须清掉该变量（见 `launcher/`）。
- 本方法只改显示语言：应用仍是官方安装、官方签名、官方授权状态，不涉及授权、激活、订阅或访问控制机制的改动。
